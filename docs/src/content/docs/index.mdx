# SKIM Framework

SKIM is a PHP 8.5+ micro-framework built around a single principle: ship only what every project actually needs, and make every decision explicit. The core has exactly two external dependencies — `nikic/fast-route` for routing and `pestphp/pest` for testing. Everything else is a deliberate choice you make. No template engine, no YAML config, no autoloaded magic — just PHP arrays, raw templates, static facades that are fully testable, and `strict_types=1` on every file.

## Design Decisions

A few things SKIM deliberately does not do:

*   **No Blade or Twig**: Raw PHP with opcache is faster, and you get real stack traces.
*   **No YAML or INI config**: PHP arrays give you IDE autocomplete and zero parse overhead.
*   **No lazy facade magic**: Static calls like `Db::` and `Cache::` are testable via `setDriver()` / `reset()`.
*   **Lazy connections**: Connections to Redis and the database are lazy — nothing opens until first use.
*   **Graceful fallback**: Cache and Redis failures fall back gracefully instead of crashing your app.

## Official Extensions

The core stays minimal. Capabilities you actually want live as official extensions that follow the same conventions.

*   **Mailer**: Wraps Symfony Mailer with 50+ SaaS transports out of the box — catch test emails locally via Ethereal without touching your real provider.
*   **Auth**: Handles the full authentication surface: registration, email verification, password reset, and social login via Google, GitHub, and Facebook.
*   More extensions are in progress.

## AI-Native Docs

SKIM's documentation pipeline is designed for both humans and machines. Each PHP file ends with a block of `#ai*` comments — placed after the class code so they never interrupt developer reading flow. These comments describe parameters, lifecycle, types, and inter-class contracts in a structured format any LLM can parse, including lightweight local models like Gemma 4 26B.

Run `php skim docs:extract` to scan `#ai*` blocks and produce a structured `llm.json` covering the entire API surface. From there, `docs:llm` flattens it to a single `llm.md` you can paste into any LLM — and `docs:site` regenerates this site from the same source.

The same pipeline works for your own application. Add `#ai*` skill comments to your project files and SKIM can run as a local MCP server — serving both framework context and your project's own architecture to any agent that asks. Your agent stops hallucinating your API because it reads the actual contracts.

## Quick Start

```bash
composer create-project skim/framework my-app
cd my-app
cp .env.example .env
docker compose up -d
php skim migrate
```

## Generate Docs

```bash
php skim docs:extract   # scan #ai* annotations → llm.json
php skim docs:llm       # llm.json → llm.md (paste into any LLM)
php skim docs:site      # llm.json → this site (MDX files)
```
