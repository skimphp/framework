# SKIM — PHP 8.5+ фреймворк для тех, кто любит PHP

## Один абзац

SKIM — это современный PHP-фреймворк, написанный с нуля под **PHP 8.5**, без груза легаси и без попыток осовременить кодовую базу двадцатилетней давности. В одной коробке: HTTP routing, Active Record ORM, query builder, cache, sessions, validation, events, Redis-очереди, CLI, DI-контейнер, Vite-интеграция, i18n, логирование, dev-тулзы и — главное — встроенный realtime-стек (SSE / Datastar / HTMX / WebSocket) и FrankenPHP worker mode. Если вам нравился PHP, но всегда не хватало скорости и реактивности Node.js — это здесь, из коробки.

---

## Почему не Laravel

Laravel — отличный зрелый фреймворк, но он несёт в себе архитектурные решения из эпохи PHP 5.x. Чтобы просто завестись на свежем PHP 8.2+, иногда приходится воевать с зависимостями, deprecation-нодами и слоями обратной совместимости. SKIM идёт другим путём:

- **PHP 8.5 как точка отсчёта, а не цель миграции.** `strict_types=1` везде, property hooks (PHP 8.4), readonly, enum'ы, first-class callable syntax — это не «добавили потом», это базис.
- **Минимум зависимостей** — одна для production (`nikic/fast-route`), одна для dev/тестов (`pest`). Никакого Symfony Console, Monolog, Twig — собственные реализации там, где чужие библиотеки тянут за собой половину экосистемы.
- **Никакого legacy-слоя.** Нет «старого» и «нового» способа сделать одно и то же. Один путь, одна конвенция.
- **snake_case везде** — классы, методы, файлы. Предсказуемость и навигация без сюрпризов, особенно когда код пишет не только человек, но и AI-агент.

## Конкуренция с Node.js — встроенный realtime

Главное, чего традиционно не хватало PHP-стеку, — это реактивность. PHP-FPM живёт в модели «запрос пришёл, процесс умер», и любой live-UI превращался в костыли с polling или отдельный Node-сервис. SKIM решает это в ядре фреймворка:

- **SSE (Server-Sent Events)** — `$res->stream(...)` стримит обновления в браузер без перезагрузки и без polling.
- **Datastar** — реактивные сигналы прямо в HTML-атрибутах, сервер патчит только изменившиеся ячейки UI.
- **HTMX** — fragment rendering из коробки, для тех, кто предпочитает классический гипермедиа-подход.
- **WebSocket** — собственный сервер в `src/websocket/`, не внешний брокер.
- **FrankenPHP worker mode** — приложение загружается один раз и крутится в цикле. Никакого cold boot на каждый запрос, никакого «PHP умирает после ответа».

Это значит, что дашборд с живыми графиками, collaborative-редактор, чат, игровой лобби — всё это теперь легитимный PHP-юзкейс, а не «давайте напишем это на Node».

## AI-first: кодовая база как источник правды для AI

SKIM спроектирован так, чтобы AI-агент работал с вашим проектом по реальным контрактам, а не по догадкам. В основе — `#ai*`-аннотации в конце PHP-файлов:

```php
// app/controllers/HomeController.php
class HomeController {
    public function index() {
        return view('home');
    }
}

#ai:class {
#  description: "Main controller responsible for rendering the landing page.",
#  lifecycle: "Instantiated per request, invoked by router."
#}
```

Эти структурированные блоки не мешают читать код человеку — они живут отдельно, в конце файла, и парсятся AST-сканером в структурированный `llm.json`. Дальше из него автоматически генерируется **подробная, точная документация** — и для людей (Astro MDX-сайт через `docs:site`), и для моделей (консолидированный `llm.md` через `docs:llm`).

### Киллер-фича: MCP-сервер под ваш собственный проект

`php skim mcp:serve` поднимает MCP-сервер, который отдаёт AI-агенту **вашу** кодовую базу: методы, контракты, схемы, lifecycle, side effects, invariants — всё, что извлечено из `#ai*`-аннотаций. Подключите к нему Claude Code, Cursor или Claude Desktop — и ассистент читает реальные контракты вместо того, чтобы галлюцинировать API.

Что это даёт на крупном проекте:

- **AI не пишет код заново, а переиспользует максимум.** Он видит существующие методы, их сигнатуры, контракты и побочные эффекты — и вызывает их, а не изобретает дубль.
- **Тысячи токенов не тратятся на поиск внутри проекта.** Вместо grep-экспедиций по репозиторию агент получает структурированный доступ через MCP — один запрос вместо десятков file-read'ов.
- **Документация никогда не расходится с кодом.** Аннотации живут в исходниках, `docs:extract` пересобирает `llm.json` за секунды — нет отдельного markdown-файла, который забыли обновить.
- **Работает с локальными моделями.** Пайплайн экстракции и генерации проверен на лёгких локальных моделях уровня Gemma 4 26B A4B — дорогие облачные LLM для генерации/использования AI-нативных доков не нужны.

Если вы любите PHP, но вам не хватало крутого и быстрого инструмента, чтобы развернуть всё за 5 минут вместе с Claude Code, Codex и другими — этот готовый проект с websockets и собственным MCP уже существует.

## Демо: PHP-FPM vs Worker Mode

В `../demo/` есть три маршрута, которые наглядно показывают разницу между классическим PHP-FPM и worker mode:

| Маршрут | Что показывает |
|---------|----------------|
| `/demo/economy` | Базовая страница City Economy Simulator — SSE + Datastar, реактивные слайдеры, live-таблица как в Excel. |
| `/demo/economy/worker` | Та же страница, но под worker mode: баннер с метриками — memory before/after reset, delta, reset time, leak detector, server latency. Видно, что приложение не перезагружается на каждый запрос. |
| `/demo/economy/stream` | Сам SSE-эндпоинт: сервер считает граф зависимостей на каждое изменение инпута и стримит обновления только изменившихся ячеек. Под FPM — cold boot на каждый слайд; под worker — persistent state, латентность в долях миллисекунды. |

Откройте `/demo/economy` под обычным PHP-FPM и под worker mode, подёргайте слайдеры — разница в отзывчивости видна без бенчмарков.

## Производительность — цифры, а не обещания

Бенчмарки прогнаны в Docker (nginx + PHP-FPM, wrk2, Apple Silicon) против Slim и Fat-Free Framework — двух самых быстрых PHP-микрофреймворков. SKIM не уступает им на холодных метриках и обгоняет на разогретых, при том что несёт в себе ORM, cache, queue, validation, events, CLI, realtime и dev-тулзы — то, что у конкурентов ставится отдельными пакетами.

### Hello World (plain text), concurrency=10

| Фреймворк | RPS | p50 (ms) | p99 (ms) |
|-----------|-----|----------|----------|
| Fat-Free | 1152 | 7.81 | 27.87 |
| **SKIM** | **1109** | 7.93 | 31.12 |
| Slim | 1055 | 7.81 | 27.87 |
| CodeIgniter 4 | 90 | 108.19 | 163.07 |

### JSON-ответ, concurrency=10

| Фреймворк | RPS | p50 (ms) | p99 (ms) |
|-----------|-----|----------|----------|
| **SKIM** | **512** | 17.83 | 53.16 |
| Slim | 505 | 18.34 | 50.26 |
| Fat-Free | 425 | 21.12 | 64.93 |
| CodeIgniter 4 | 83 | 117.17 | 185.83 |

### Router stress (1000 маршрутов)

| Фреймворк | RPS | p50 (ms) | p99 (ms) |
|-----------|-----|----------|----------|
| **SKIM** | **487** | 99.18 | 272.44 |
| Slim | 467 | 107.33 | 289.28 |
| Fat-Free | 413 | 138.35 | 212.83 |

### Cold start после рестарта PHP-FPM

| Фреймворк | Cold avg (ms) | Warm avg (ms) | Overhead |
|-----------|---------------|---------------|----------|
| **SKIM** | **30.5** | 15.48 | ~15 ms |
| Slim | 33.7 | 18.69 | ~15 ms |
| Fat-Free | 59.09 | 32.71 | ~26 ms |

Cold-start overhead — это прогрев OPcache, он не специфичен для SKIM и платится любым PHP-приложением один раз. После прогрева SKIM выходит на ~15 ms average.

### FrankenPHP worker mode — совсем другая лига

Worker mode — это не «ещё один режим», это смена модели выполнения. Приложение загружается один раз (`app::instance() → boot() → boot_extensions() → freeze()`) и крутится в цикле, обрабатывая запросы без cold boot. Локальный бенчмарк `benchmarks/worker_mode_benchmark.php` поднимает TCP-сервер и гоняет запросы через `begin_request() → dispatch() → send() → end_request()`:

- **Hello World, single worker: ~1600–1800 RPS**, avg ~0.56 ms, p95 ~0.92 ms.
- **JSON, single worker: ~1650–1800 RPS**, avg ~0.55 ms, p95 ~0.84 ms.

Для сравнения: те же эндпоинты под PHP-FPM с 8 workers дают ~1500 RPS — и это с параллелизмом. Один worker mode-процесс перегоняет FPM-пул по латентности на порядок, потому что нет bootstrap'а на запрос. На bare metal с Caddy + FrankenPHP будет ещё быстрее.

Под капотом worker mode защищён от утечек памяти: `worker_reset` сбрасывает resettable-классы между запросами, `leak_detector` отслеживает накопление, soak-тест прогоняет 1000 запросов через worker loop с проверкой memory growth. Это не «запустил и молись» — это контракт.

## Dev-тулзы — ошибки, которые приятно читать

SKIM ships с dev-инструментами, которые обычно приходится ставить отдельно (Symfony VarDumper, Whoops, Clockwork, Debugbar). Здесь они в ядре и заточены под фреймворк:

### Error page (когда `APP_DEBUG=true`)

Это не стандартный PHP stack trace. На одной странице:

- **Контекст кода** — ±10 строк вокруг ошибки с PHP-синтаксис-хайлайтингом, проблемная строка подсвечена.
- **Стек разбит на три секции** — Application / Request Pipeline / Framework. Шум фреймворка свёрнут по умолчанию, ваши кадры — на виду.
- **Аргументы фреймов** — отражённые значения аргументов с раскрытием свойств объектов, не просто `array(2)`.
- **DI-дерево** для контроллера — что резолвилось, какие биндинги сработали.
- **Env / request / route / middleware** — всё в одном месте, без `dd($_SERVER)`.
- **IDE-ссылки** — клик по файлу:строка открывает редактор (VS Code, PhpStorm, Sublime — автоопределение).
- **Suggestions** — на `Call to undefined method` предлагает похожие методы через Levenshtein: «Did you mean `index()`?»
- **Секреты затираются** — `password`, `secret`, `token`, `api_key`, `credentials` и ~15 подобных ключей автоматически маскируются в env и аргументах. Ничего не утекает на экран.
- **Fallback** — если упал сам шаблон error page, рендерится минимальный inline HTML, чтобы разработчик всё равно увидел ошибку.

### Debug toolbar

Фиксированная панель внизу страницы (только для `text/html`, не для JSON/AJAX). Табы:

- **Request** — метод, путь, итоговое время, peak memory.
- **DB** — все SQL-запросы с интерполированным текстом, временем и числом строк; таб краснеет при >20 запросов (N+1-детектор).
- **Cache** — hits/misses, ratio, driver, ключи.
- **Timeline** — распределение времени по фазам запроса.
- **Views** — какие шаблоны рендерились, включая fragments.
- **Logs** — записи логгера за этот запрос.

### Profiler

Статический коллектор событий: DB-запросы, cache-операции, view-рендеры, log-записи. Вызывается ядром автоматически — `profiler::db()`, `profiler::cache()`, `profiler::view()`. В production всё no-op, нулевой overhead. Кастомные панели регистрируются через `profiler::panel()` — можно добавить свою метрику в toolbar.

## CLI — `php skim` как швейцарский нож

Собственный CLI-фреймворк, не Symfony Console. TUI-меню с поиском при запуске без аргументов в TTY, ANSI-цвета только в терминале (безопасно для CI/pipe), stderr-роутинг ошибок. Команды:

- **`skim install`** — интерактивный установщик: генерит `.env` из промптов, опционально прогоняет миграции.
- **`skim serve`** — PHP dev-сервер + Vite HMR параллельно через `proc_open`, оба убиваются по Ctrl+C.
- **`skim migrate`** — `run` / `rollback` / `fresh` / `status` / `make`. Поддержка sub-команд через двоеточие.
- **`skim cache:build`** — компилирует env, config и расширения в чистые PHP-массивы для OPcache. Убирает runtime-discovery.
- **`skim cache:clear`** — инвалидация по префиксу или полный flush.
- **`skim queue`** — `work` / `status` / `flush` / `restart` для Redis-очередей.
- **`skim ext:list`** — список установленных расширений с capability и conflict-репортом.
- **`skim ext:install`** — ставит SKIM-extension через composer, публикует конфиг, прогоняет миграции атомарно.
- **`skim ext:manifest`** — генерирует `skim.json` манифест из класса расширения для дистрибуции.
- **`skim ide:helper`** — генерирует `.ide-helper.php` с typed-стабами свойств моделей для автокомплита в IDE.
- **`skim worker:install`** — генерирует FrankenPHP worker mode файлы: `public/worker.php`, `Caddyfile`, `docker/Dockerfile.frankenphp`. Один скоффолд — и проект готов к production worker mode.
- **`skim worker:uninstall`** — убирает worker-файлы.
- **`skim docs:extract`** — парсит `#ai*`-аннотации в `llm.json`.
- **`skim docs:llm`** — консолидирует `llm.json` в `llm.md` для моделей.
- **`skim docs:site`** — собирает Astro MDX-сайт документации из `llm.json`.
- **`skim docs:validate`** — проверяет аннотации на консистентность.
- **`skim mcp:serve`** — поднимает MCP-сервер для Claude Code / Cursor / Claude Desktop.

Свои команды регистрируются в `config/app.php` под ключом `commands` — одна строка, и `php skim my:command` работает.

## Полный стек в одном пакете

Не нужно собирать приложение из десятка пакетов — всё уже в ядре:

- **HTTP**: роутинг с группами и параметрами, middleware pipeline, request/response.
- **DB**: Active Record с property hooks для dirty tracking и авто-нормализации, query builder, миграции.
- **Cache**: Redis / file / array с единым интерфейсом.
- **Sessions**: Redis с fallback.
- **Validation**: pipe-синтаксис (`string|trim|min:3|max:255`).
- **Events**: синхронные и в очередь.
- **Queue**: Redis-based background jobs.
- **CLI**: собственный `bin/skim` с командами (migrate, seed, ext:list, …).
- **DI**: контейнер с 3 скоупами.
- **Assets**: Vite-интеграция — HMR в dev, hashed filenames в prod.
- **Realtime**: SSE, Datastar, HTMX fragments, WebSocket.
- **Worker**: FrankenPHP worker mode с leak detector и resettable-контрактом.
- **Dev-тулзы**: error page с suggestions и IDE-ссылками, debug toolbar, profiler — см. отдельную секцию выше.
- **CLI**: `php skim` с установщиком, миграциями, очередями, расширениями, worker-скоффолдом, AI-докпайплайном и MCP-сервером — см. отдельную секцию выше.
- **i18n, логирование.**
- **Расширения через Composer** с декларацией capabilities и обнаружением конфликтов (готовые `Auth` и `Mailer`).

## Кому это

- **PHP-разработчикам**, которым надоело тащить легаси и хочется писать на современном языке без боя с фреймворком.
- **Командам, выбирающим между PHP и Node.js** для realtime-приложения — теперь PHP может в realtime нативно.
- **AI-нативным разработчикам**, которые хотят, чтобы Claude Code / Codex / другие агенты выдавали готовый проект за одну сессию, а не «приблизительно работающий».
- **Тем, кто разворачивает MVP за вечер** — `docker compose up` и есть рабочий стек с websockets.
